## **Основной функционал:**

Приложение разбито на несколько страниц. Каждая выполняет свою узкоспециализированную функцию.



### Список сборочных единиц:

**Блок управления:**

* Поле поиска сверху. Рядом с полем поиска чекбокс показать архивные элементы или нет.

* Под полем поиска находится дропдаун для выбора холодильной установки. Справа от него дропдаун выбора сборочного узла, относящегося к этой холодильной установке. Ещё правее дропдаун выбора деталей, относящихся к этому сборочному узлу.

* Все дропдауны, кроме выбора холодильной установки, неактивны, если не выбрана холодильная установка.



**Список карточек:**

* При выборе карточки отображается sticky блок с кнопками удаления и архивации.

* Кнопка сортировки по типу элемента, дате, названию.

* Кнопка группирования карточек по холодильной установке и сборочному узлу.



**Карточка:**

* Иконка типа элемента в левом верхнем углу 

* Цвет позволяет легко понять, что за тип карточки перед нами

* Текстовое представление данных отображаемого элемента (название, чертеж, типа элемента итд)

* Для холодильных установок: список сборочных узлов с их количеством на установку

* Для сборочных узлов: список деталей с их количеством на узел



В поле поиска вводим название или номер чертежа. 



Под блоком фильтра (поле поиска,  дропдауны итд) отображаем найденные холодильные установки, сборочные узлы, детали сборочных узлов. У каждого своя карточка. Карточки отличаются цветовым кодированием и иконкой. Карточки архивных элементов имеют прозрачность, чтобы визуально меньше выделяться.



Если поле поиска пусто, то не отображаем ничего, пока пользователь не выберет холодильную установку в дропдауне.



Если выбрана холодильная установка, показываем все, относящиеся к ней элементы. При этом, если ввести в поле поиска текст, то поиск будет идти уже только по выбранной в дропдауне холодильной установке.



При наведении на карточку появляется чекбокс. При выборе карточки, она визуально выделяется.

Если выбрана хоть одна карточка в верхнем правом углу появляется sticky блок с кнопками для удаления выбранных элементов, либо для их архивирования или разархивирования.



Кроме того, при наведении на карточку появляется кнопка редактирования.

При нажатии, открывается модальное окно для редактирования данных единицы.

Для холодильных установок и сборочных узлов должен быть блок добавления дочерних элементов (сборочных узлов для холодильной установки и деталей для сборочных узлов). В блоке помимо поля, отображающего добавленные элементы, будет поле поиска в котором при вводе текста будут отображаться отфильтрованные элементы в дропдаун списке. Если поле пустое, отображается весь список. При нажатии на элемент, он добавляется в список. Должна быть предусмотрена возможность увеличить количество выбранного элемента или удалить его из списка.

При сохранении, обновляются данные в БД. Также можно отменить сохранение изменений, закрыть модальное окно (клик вне модального окна, кнопка закрытия, клавиша escape).

### Подсчет текущего наличия и излишкев:

**Блок управления:**

* Дропдаун выбора холодильной установки. При нажатии на дропдаун можно ввести текст и тогда список в дропдауне будет отфильтрован по введенному тексту.

* Поле ввода номера уже готовой холодильной установки. По-умолчанию берём из БД, но можно изменить вручную.



При выборе холодильной установки отображается список карточек сборочных узлов, относящихся к этой установке, а в поле ввода номера готовой установки подставляется номер из БД.



В карточках в списке деталей, у каждой детали появляются поля с количеством. В них вводится количество этих деталей в наличии на складе.

Под карточкой блок статистики в котором отображается сколько комплектов можно собрать имеющимися деталями, а также остаток деталей после сборки этих комплектов. Показываем номер холодильной установки, которая будет закрыта этим сборочным узлом после сборки комплектов.



Под списком карточек общая статистика, сколько полных холодильных установок можно собрать с получившимися сборочными узлами.



Кнопка сохранить. При нажатии выдает попап уверен ли пользователь, что он хочет внести изменения в БД. При согласии, обновляет номер последней готовой установки по сборочным узлам вычисленным при подсчете номером.

### Список изоляции и отслеживание прогресса нарезания:



**Блок управления:**

* Два дропдауна:  Первый – выбор холодильной установки. Второй – выбор версии (дата). По-умолчанию при выборе установки ставится самая актуальная.

* Инпут номера установки. Вводится вручную.



При выборе холодильной установки выбирается автоматически версия по дате (наиболее актуальная). 

Отображаются группы теплоизоляции.

В каждой группе отображаются название группы, кнопка сворачивания группы (аккордеон), карточки кусков изоляции.

У каждой группы есть кнопки: отметить все готовым – отмечает все куски в группе готовыми и наоборот снять готовность.

При нажатии на карточку куска изоляции он помечается готовым. Если выделены все куски в группе, то группа помечается готовой.

В подвале каждой группы отображаем статистику, сколько и какая по толщине теплоизоляция была использована на эту группу в квадратных метрах.



Под списком групп отображаем общую статистику по использованной теплоизоляции. Отображаем круглый чарт, где наглядно демонстрируем какая группа использовала намболее большую площадь. А также чарт сравнение использования теплоизоляции разной толщины.



Далее отображаем кнопки: отметить все готовым, снять готовность и сохранить.

При нажатии на кнопку сохранить показываем попап меню, где спрашиваем, уверен ли пользователь. Если уверен, обновляем в БД номер последней готовой установки по изоляции.



Подумай, как лучше сохранять прогресс выполнения, если человек не успел доделать и отложил на следующий день. Нужно сохранять состояние готовых/не готовых кусков и групп. Возможно, добавить ещё одну сущность, но хотелось бы что-то более элегантное. Могут использоваться разные устройства, поэтому local storage не подойдёт.

### Сайдбар:

Слева вертикально во всю высоту страницы. При клике вне сайдбара закрывается. Должен содержать в себе кнопку открытия/закрытия сайдбара, навигацию по основным страницам, пункты меню для настроек (пока неактивно) и общей статистики (пока неактивно).

Внизу показываем блок пользователя (берём данные пользователя из БД, так как у нас пока нет авторизации и регистрации).



При закрытии сворачивается до узкой полосы слева экрана отображая только кнопку открытия сайдбара, иконки пунктов меню и аватарку пользователя.



В мобильной версии уезжает горизонтально в верхнюю часть экрана и становится зафиксированным в этом положении. При открытии горизонтальная полоса остаётся наверху, а под ней открывается полный сайдбар.



Пункты меню не должны быть жёстко вшиты, а создаваться динамически из объекта меню. Объект меню должен содержать всю необходимую информацию о пунктах в сайдбаре (иконка, название, адрес итд).
