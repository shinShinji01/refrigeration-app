# Замеры и постоянный размер маркеров в `features/shape-editor` — Design

## Контекст

Первая версия `ShapeEditor` (`docs/superpowers/specs/2026-08-15-shape-editor-design.md`,
реализована и провалидирована в `docs/superpowers/plans/2026-08-15-shape-editor.md`)
рисует контур, но:

1. Маркер вершины — фиксированный радиус 4мм **в координатах чертежа**. На маленьких
   кусках (десятки мм) и на сильном ручном зуме он визуально доминирует над фигурой —
   неудобно ставить и различать соседние точки.
2. Длины сторон нигде не видны, кроме общей площади в живом отчёте под канвасом.
   Пока рисуешь контур, нет обратной связи о размере текущего отрезка.

Это увеличение по итогам ручной проверки первой версии в браузере (см. фидбек
пользователя после Task 12 плана shape-editor). Меняем только визуальное
представление и взаимодействие внутри `ShapeEditor` — модель данных
(`Geometry`, `editorReducer`) не трогаем.

## Архитектура

### Пересчёт мм↔px

Канвас — квадратный SVG с `viewBox` в мм чертежа, отрендеренный в CSS-пикселях
шириной `width: 100%; max-width: 360px` (реальная ширина на телефоне может быть
меньше 360px — mobile first, CLAUDE.md). Чтобы маркеры вершин и подписи длины
имели **постоянный размер на экране** независимо от зума и размера контура, нужен
коэффициент мм-на-пиксель, посчитанный от фактической отрендеренной ширины, а не
от CSS-константы.

В `useShapeEditor.ts`:

```ts
const [canvasPixelSize, setCanvasPixelSize] = useState(360) // фолбэк до первого измерения

useEffect(() => {
  const svg = svgRef.current
  if (!svg) return
  const observer = new ResizeObserver((entries) => {
    const width = entries[0]?.contentRect.width
    if (width) setCanvasPixelSize(width)
  })
  observer.observe(svg)
  return () => observer.disconnect()
}, [])

const mmPerPx = viewBox.width / canvasPixelSize
```

Новые константы (px, переводятся в мм через `mmPerPx`):

```ts
const VERTEX_VISIBLE_RADIUS_PX = 6
const VERTEX_HIT_RADIUS_PX = 22 // диаметр 44px — тач-таргет из CLAUDE.md
const LABEL_FONT_SIZE_PX = 11
```

Хук возвращает вычисленные `vertexRadiusMm`, `vertexHitRadiusMm`, `labelFontSizeMm`
в составе `UseShapeEditorResult` — `ShapeEditor.tsx` не занимается пересчётом сам,
только подставляет готовые значения в SVG-атрибуты.

`ResizeObserver` не реализован в jsdom — юнит-тесты `useShapeEditor`/`ShapeEditor`
мокают его глобально в setup-файле теста (см. Тестирование).

### Маркеры вершин: видимый + тач-зона

Каждая точка контура рендерится **двумя** `<circle>` в одном месте:

- невидимый снизу, `r={vertexHitRadiusMm}`, `fill="transparent"`, несёт
  `{...getVertexHandlers(index)}` — весь drag обрабатывается им;
- видимый сверху, `r={vertexRadiusMm}`, текущие классы `.vertex`/`.vertexInvalid`,
  `pointer-events: none` — чисто декоративный, в обработке событий не участвует.

Так видимый кружок компактный и не загораживает фигуру, а зона попадания пальцем
не сжимается вместе с ним.

### Подписи длины сторон

Новая чистая функция `lib/segmentLabel.ts`:

```ts
interface SegmentLabel {
  midpoint: Point
  angleDeg: number // нормализован в [-90, 90] — текст никогда не вверх ногами
  lengthMm: number
}

export const segmentLabel = (a: Point, b: Point): SegmentLabel => { ... }
```

`angleDeg` — угол наклона отрезка в градусах; если сырой угол выходит за пределы
±90° (сторона идёт «справа налево»), к нему добавляется 180°, чтобы `<text>` с
`transform="rotate(angleDeg, ...)"` всегда читался слева направо, не переворачиваясь.

В `ShapeEditor.tsx`: для каждой пары соседних точек текущего контура (при
рисовании — все уже поставленные сегменты, на замкнутом — все стороны, включая
замыкающую) рендерим `<text>` в `midpoint`, смещённый на фиксированный отступ
(в px через `mmPerPx`, чтобы отступ тоже не зависел от зума) вдоль нормали к
отрезку — нормаль берётся поворотом направляющего вектора на -90°, то есть
подпись всегда с одной и той же стороны относительно направления обхода точек.
Для невыпуклых контуров это не гарантирует «снаружи фигуры» в общем случае, но
не требует анализа фигуры целиком и достаточно для реальных кусков изоляции
(в основном прямоугольники и простые многоугольники) — если на практике подпись
будет попадать внутрь заливки, это видно на самой заливке `$color-accent-cyan-muted`
и не мешает читать текст. `transform="rotate(angleDeg, x, y)"`,
`font-size={labelFontSizeMm}`, текст — `Math.round(lengthMm)` + «мм». Один и тот же
рендер-хелпер используется и для сторон контура, и для превью-линии (см. ниже).

Целые мм: округление достаточно для раскроя изоляции, лишняя точность только шумит
(ср. существующий формат площади `0.06 м²` в живом отчёте — не десятые доли мм²).

### Живая линия-превью (только мышь)

Новое состояние в `useShapeEditor.ts` — `hoverPointMm: Point | null`. Расширяем
существующий `handlePointerMove`: пока контур не замкнут, активен один указатель
(не pinch) и `event.pointerType === 'mouse'` — обновляем
`hoverPointMm = snapToGrid(clientToMm(...))`. Новый `handlePointerLeave` сбрасывает
`hoverPointMm` в `null`, когда курсор уходит с канваса.

На touch `pointerType` никогда не `'mouse'`, поэтому `hoverPointMm` там не
выставляется вовсе — превью-линия существует только для десктопа, что и
требовалось: на тач-устройстве нет hover до касания, а жест «драг перед
отпусканием» сознательно не реализуем (лишняя сложность ради сомнительного
выигрыша при точечных тапах).

В `ShapeEditor.tsx`: если `status === 'drawing'`, есть хотя бы одна точка и
`hoverPointMm` задан — рисуем пунктирную `<line>` от последней точки контура до
`hoverPointMm` (класс `.previewLine`: тот же `$color-accent-cyan`, но пунктир и
пониженная непрозрачность — отличать от уже закоммиченных сторон) и такую же
подпись длины через `segmentLabel`.

### Затронутые файлы

- `model/useShapeEditor.ts` — `ResizeObserver`/`canvasPixelSize`, `hoverPointMm`,
  `handlePointerLeave`, вычисляемые `vertexRadiusMm`/`vertexHitRadiusMm`/
  `labelFontSizeMm`, всё — в `UseShapeEditorResult`.
- `ui/ShapeEditor.tsx` — двойные `<circle>` на вершину, `<text>`-подписи на каждой
  стороне и на превью-линии, `onPointerLeave` на `<svg>`.
- `ui/ShapeEditor.module.scss` — новые классы `.previewLine`, `.sideLabel`.
- Новый `lib/segmentLabel.ts` + `lib/segmentLabel.test.ts`.
- Тестовый setup для `shape-editor` — мок `ResizeObserver` (глобально недоступен в
  jsdom).

Модель (`editorReducer`, `Geometry`, `classifyContour` и т.д.) не меняется — это
чисто рендер/интеракция поверх существующего состояния.

## Граничные случаи

- `canvasPixelSize` до первого срабатывания `ResizeObserver` (первый рендер) —
  используем фолбэк 360, чтобы не делить на 0 и не показывать на долю секунды
  неверный размер маркера.
- Вырожденный сегмент (совпадающие точки, `lengthMm === 0`) — подпись не рендерим
  вовсе (нечего подписывать, `angleDeg` не определён).
- Превью-линия при `hoverPointMm`, совпадающем с последней точкой (курсор не
  двигался с момента постановки) — длина 0, подпись не рендерится (тот же case,
  что и выше).
- Ресайз окна/поворот экрана на телефоне — `ResizeObserver` пересчитывает
  `canvasPixelSize`, маркеры и подписи остаются постоянного видимого размера.

## Тестирование

- `lib/segmentLabel.test.ts` — горизонтальный/вертикальный/диагональный сегмент,
  нормализация угла для сторон, направленных «справа налево» (не переворачивается),
  округление длины, вырожденный сегмент (совпадающие точки).
- `model/useShapeEditor.test.ts` (расширение существующего) — глобальный мок
  `ResizeObserver` в setup; `hoverPointMm` обновляется на `pointerType: 'mouse'` и
  не обновляется на `'touch'`; сбрасывается на `pointerleave`.
- `ui/ShapeEditor.test.tsx` (расширение существующего) — подписи длины
  рендерятся для каждой стороны рисуемого и замкнутого контура; превью-линия и её
  подпись появляются/исчезают вместе с `hoverPointMm`.
