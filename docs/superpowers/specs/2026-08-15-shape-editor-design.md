# Графический редактор геометрии куска изоляции (`features/shape-editor`) — Design

## Контекст

`docs/spec.md` описывает кусок теплоизоляции с размерами «прямоугольник либо
многоугольник», `docs/decisions.md` (№6) фиксирует, что площадь хранится как
денормализованное поле, а `docs/data-model.md` уже описывает тип `Geometry`
(дискриминированное объединение `rect | polygon`) и единственную точку
пересчёта площади — `withComputedArea()`. Само решение выбрать веб/Capacitor
вместо React Native (`docs/decisions.md`) прямо аргументировано тем, что
редактор геометрии куска — это SVG, бесплатный в вебе.

Сейчас в коде есть только заготовки: `shared/lib/geometry/types.ts` содержит
типы `Point`/`Geometry`, но не `computeArea`/`withComputedArea`; `features/
shape-editor/.gitkeep` — пустой слайс. Форм создания/редактирования кусков и
групп изоляции тоже ещё нет — это будет отдельный спек. Этот документ
описывает только сам графический редактор геометрии как изолированный
компонент — переиспользуемый и в будущей форме создания куска, и в форме
редактирования существующего.

Разговор с пользователем (2026-08-15) зафиксировал ключевые решения:

- Точный чертёж по сетке 5мм, а не свободное рисование «на глаз».
- Единый инструмент рисования без переключателя «прямоугольник/
  многоугольник» — тип определяется автоматически по итоговому контуру.
- Редактирование уже поставленных точек: драг точки, отмена последней,
  полный сброс. Без вставки/удаления точек в середине готового контура.
- Zoom — и кнопками, и жестами (pinch/колесо) одновременно.
- Контролируемое поле формы (`value`/`onChange`), без своего локального
  Сохранить/Отмена.
- Живой числовой отчёт (тип + площадь) во время рисования.
- Невалидный контур (<3 точек, самопересечение) блокирует замыкание/анлайн-
  правки, наружу никогда не уходит невалидная геометрия.

## Архитектура

### Расположение

```
src/shared/lib/geometry/
  computeArea.ts            — rect: width*height; polygon: формула шнурков
  computeArea.test.ts
  withComputedArea.ts       — уже описан в data-model.md, физически не создан
  withComputedArea.test.ts

src/features/shape-editor/
  ui/ShapeEditor.tsx        — SVG-канвас, pointer-события, тулбар, живой отчёт
  ui/ShapeEditor.module.scss
  lib/classifyContour.ts    — Point[] (замкнутый) → Geometry
  lib/classifyContour.test.ts
  lib/snapToGrid.ts         — px ↔ mm, привязка к шагу 5мм
  lib/snapToGrid.test.ts
  lib/hasSelfIntersection.ts
  lib/hasSelfIntersection.test.ts
  lib/fitScale.ts           — масштаб под bounding box контура + отступы
  lib/fitScale.test.ts
  index.ts
```

`computeArea`/`withComputedArea` физически отсутствуют, хотя уже описаны в
`docs/data-model.md` — реализуются в рамках этой задачи, т.к. живой отчёт
редактора использует `computeArea` напрямую (без денормализации — это
скоротечное значение на экране, не хранимое поле).

### Контракт компонента

```ts
interface ShapeEditorProps {
  value: Geometry | null // null — пустой контур
  onChange: (geometry: Geometry | null) => void
}
```

Обычное controlled-поле, без знания о форме/домене. Подключается через
`react-hook-form` `Controller`, аналогично остальным полям в
`ComponentEditModal`:

```tsx
<Controller
  name="geometry"
  control={control}
  render={({ field }) => <ShapeEditor value={field.value} onChange={field.onChange} />}
/>
```

Внутреннее состояние процесса построения (текущий незамкнутый контур,
масштаб, был ли зум тронут вручную) — локальный `useReducer` в
`ShapeEditor`, наружу никогда не течёт: `onChange` вызывается только с
финальной валидной `Geometry` (или `null` при полном сбросе), никогда с
промежуточным «недорисованным» состоянием.

### Состояния контура

`empty` (точек нет, `value === null`) → `drawing` (1+ точек, не замкнут,
`value` снаружи всё ещё `null`, потому что незамкнутый контур не является
валидной геометрией) → `closed` (замкнут, `value` — валидный `rect` или
`polygon`).

### Построение контура

- **Тап по пустому канвасу** — добавляет точку, снапнутую к сетке 5мм
  (`snapToGrid`). Все точки лежат на одной сетке, поэтому «попадание в
  первую точку» — точное совпадение координат после снапа, без радиуса
  попадания и эпсилон-допусков. Если снапнутая точка совпадает с первой
  точкой контура, точек уже ≥3 и контур не самопересекается — вместо
  добавления точки контур замыкается: `classifyContour` определяет
  `rect`/`polygon`, вызывается `onChange`.
- **Drag по пустому канвасу при 0 точек** — быстрый прямоугольник: отпустили
  — сразу замкнутый `rect` между стартовой и конечной точкой (снап углов).
  Как только хотя бы одна точка полигона уже поставлена тапом, drag-жест
  для прямоугольника отключается — иначе неоднозначность между «новый
  прямоугольник» и «дёрнуть уже начатый контур».
- **Кнопка «Замкнуть»** (активна при ≥3 точках без самопересечения) —
  альтернатива тапу точно в первую точку, важна для touch, где точное
  попадание в уже поставленную точку неудобно.
- **Кнопка «Назад»** — убирает последнюю поставленную точку.
- **Кнопка «Очистить»** — сброс в `empty`, `onChange(null)`.

### Редактирование замкнутого контура

Драг существующей вершины двигает её (снап к сетке), контур **живо
переклассифицируется** на каждый снап-шаг — например, оттянутый не по оси
угол прямоугольника превращает `rect` в `polygon`. `onChange` вызывается на
каждом снап-шаге во время драга и по отпусканию (не на каждый пиксель — снап
естественно ограничивает частоту).

Если во время драга контур становится самопересекающимся — стороны
подсвечиваются `$color-red`, но `onChange` не вызывается, пока пересечение
не исправлено: снаружи всегда лежит последняя валидная геометрия, а не
временный битый контур.

Вставка/удаление вершин в готовом контуре не поддерживается — только «Очистить»
и рисование заново.

### Классификация (`classifyContour`)

Точки уже снапнуты к сетке, поэтому сравнение координат точное:

```ts
export const classifyContour = (points: Point[]): Geometry => {
  if (points.length === 4 && isAxisAlignedRect(points)) {
    const [p0, , p2] = points
    return { kind: 'rect', width: Math.abs(p2.x - p0.x), height: Math.abs(p2.y - p0.y) }
  }
  return { kind: 'polygon', vertices: points }
}
```

`isAxisAlignedRect` проверяет, что стороны попарно параллельны осям (X или Y
координаты соседних точек совпадают по кругу) — без эпсилон-допусков, т.к.
все точки уже кратны 5мм.

### Зум и viewport

Кнопки `+`/`−` в тулбаре и жесты (pinch на touch через `pointermove` с двумя
активными указателями, `wheel` на десктопе) управляют одним и тем же
значением масштаба в состоянии редактора. Авто-fit (`fitScale`) пересчитывает
масштаб под bounding box контура при каждом изменении геометрии, **пока
пользователь не менял зум вручную** в текущей сессии редактирования этого
поля — иначе автоподстройка перебивала бы ручной зум при каждой новой точке.
Кнопка «По размеру» сбрасывает флаг ручного зума и возвращает к авто-fit.

Панорамирование не реализуется отдельным жестом — если зум больше, чем
авто-fit, канвас становится нативно скроллируемым контейнером
(`overflow: auto`), что не конфликтует с рисованием одним указателем.

### Живой отчёт

Под канвасом — моноширинная строка с табличными цифрами, обновляется на
каждое изменение контура (в т.ч. незамкнутого — площадь для незамкнутого
контура не считается, показывается только количество точек):

- `drawing`, <3 точек: «Поставьте ещё N точек»
- `drawing`, ≥3 точек: «Можно замкнуть»
- `closed`, rect: `rect 300×200 мм · 0.06 м²`
- `closed`, polygon: `polygon · 0.14 м²`

### Визуальный стиль

По направлению из `CLAUDE.md` («чертёж и раскройная карта»):

- Сетка — hairline `$color-graphite-100` каждые 5мм, более плотная линия с
  подписью в мм (`$font-family-mono`, `tabular-nums`) каждые 50мм.
- Активный контур и вершины — `$color-accent-cyan`, заливка —
  `$color-accent-cyan-muted`.
- Самопересечение — конфликтующие стороны и точка пересечения —
  `$color-red`.
- Кнопки тулбара — обычные кнопки ui-kit: `focus-ring` на фокусе, тач-таргет
  ≥44px. `prefers-reduced-motion` отключает подсветку при замыкании/ошибке —
  она становится мгновенной, без transition.

## Граничные случаи

- Попытка замкнуть контур с <3 точками — кнопка «Замкнуть» задизейблена,
  тап в точку с координатами первой точки не засчитывается как замыкание
  (интерпретируется как обычная новая точка — просто ляжет поверх первой).
- Самопересекающийся контур при первом замыкании — тем же способом, что и
  при драге вершины: подсветка красным, замыкание не происходит.
- `value` приходит извне с уже существующей геометрией (режим редактирования
  куска) — рендерится сразу в состоянии `closed`, `fitScale` подстраивает
  масштаб под неё при монтировании.
- `value` становится `null` извне (например, сброс формы) — редактор
  возвращается в `empty`, локальное состояние точек и флаг ручного зума
  сбрасываются.
- Двойное быстрое нажатие «Назад» до `empty` — кнопка задизейблена при 0
  точек, дальнейшие нажатия невозможны.
- Zoom pinch одновременно с рисованием точки (два указателя, один из них
  только что поставил точку) — pinch распознаётся только когда оба указателя
  активны одновременно с самого начала жеста; одиночный указатель всегда
  трактуется как рисование/драг вершины, не как начало pinch.

## Тестирование

Чистая логика — полное юнит-покрытие:

- `computeArea`/`withComputedArea` (`shared/lib/geometry`) — rect и polygon
  (включая невыпуклый), нулевая площадь на вырожденном контуре.
- `classifyContour` — 4 точки осевой прямоугольник → `rect`; 4 точки не по
  осям (ромб) → `polygon`; 3 точки → `polygon`; 5+ точек → `polygon`.
- `snapToGrid` — округление px→мм к ближайшим 5мм в обе стороны, граничные
  значения (ровно посередине между двумя узлами сетки).
- `hasSelfIntersection` — простой невыпуклый контур без пересечений (false),
  контур типа «бабочка» (true), пересечение смежных сторон в общей вершине
  не считается самопересечением (false).
- `fitScale` — масштаб для маленького контура (десятки мм) и большого
  (метры) укладывается в заданные границы канваса с отступом.

`ShapeEditor.tsx` — RTL-тесты: рендер корректного SVG-контура по заданному
`value` (rect/polygon/null), вызов `onChange` с ожидаемой геометрией на
симулированной последовательности pointer-событий (down/move/up с
координатами) для сценариев: построить прямоугольник драгом, построить
многоугольник тапами, замкнуть кнопкой, подвинуть вершину, самопересечение
блокирует `onChange`. Объём — сравнимый с другими интерактивными
компонентами кодовой базы (`CascadeFilter`, `SortButton`).

Реальную тактильность (touch drag, pinch, снап на маленьком экране) юнит-
тесты не покрывают — проверяется вручную через `pnpm dev` + `pnpm pb` в
браузере (мышь + touch-эмуляция) перед сдачей, аналогично проверке
клик-навигации в `2026-08-14-units-card-navigation-design.md`.
